# Auditing Anneal Documentation, Examples, and CLI Instructions (`anneal-doc-audit`)

Verify that every Markdown tutorial, reference guide, skill definition, and
runnable example in the Anneal repository stays in lockstep with the live
`cargo-anneal` CLI, `anneal-rustc-capture` driver, and Lean 4 libraries
(`Trusted.*` and `Anneal.*`).

## 1. Automated Verification Gate (Run First)

Before manually inspecting documentation files, run the automated documentation
and tutor verification suite in `crates/cargo-anneal/tests/end_to_end_tutor.rs`:

```bash
# Fast (<1s) structural, link, CLI-parser, two-flavour, and code/report sync check:
cargo test -p cargo-anneal --test end_to_end_tutor tutor_and_repo_docs_links_cli_flavours_and_reports_stay_in_sync --locked

# Fast (<1s) directive and coverage check for the tutor chapters:
python3 docs/tutor/workflow/tutor_workflow.py lint

# Full end-to-end Tutor progression (Flavour A relative `--manifest-path`,
# Flavour B in-crate `cargo anneal`, Chapters 1–6, Lake build, TrustedBoundary,
# and the rendered-block check against docs/tutor/workflow/tutor.toml):
cargo test -p cargo-anneal --test end_to_end_tutor --locked
```

When `tutor_chapters_match_the_tutor_workflow` fails after an intentional CLI
or tutorial change, regenerate the managed blocks and review the resulting diff
rather than editing them by hand:

```bash
python3 docs/tutor/workflow/tutor_workflow.py render
```

Commands, reports, error messages, and file listings inside
`<!-- tutor: ... -->` directives are generated from
`docs/tutor/workflow/tutor.toml` (see `docs/tutor/workflow/README.md`); the
manual checklist below covers what that generator cannot judge.

## 2. Five-Point Freshness & Pedagogical Audit Checklist

When running a periodic or post-change audit across `README.md`, `docs/**/*.md`,
`examples/**/*.md`, and `skills/**/SKILL.md`, verify all five invariants:

### Invariant A — Relative Markdown Link Integrity
- Every non-URL Markdown link `[label](relative/path.md#anchor)` outside fenced
  code blocks must resolve to an existing file or directory relative to the
  containing Markdown file.
- If chapters, modules, or archived research directories are renamed or moved,
  update all cross-links in `README.md`, `docs/tutor/README.md`,
  `examples/tutor/README.md`, and chapter navigation headers.

### Invariant B — Dual-Flavour CLI Instructions in Tutorials
- Every executable `cargo anneal` command block in `docs/tutor/01-*.md` through
  `docs/tutor/06-*.md` (and `docs/tutor/README.md` / `examples/tutor/README.md`)
  must present **both invocation flavours**:
  1. **Flavour A — Inside an Anneal checkout**:
     `cargo run -p cargo-anneal -- <subcommand> [FLAGS] --manifest-path examples/tutor/Cargo.toml`
     (preceded in setup sections by `cargo build -p anneal-rustc-capture -p cargo-anneal`).
  2. **Flavour B — Using installed `cargo anneal` outside the checkout (or inside the target crate)**:
     `cargo anneal <subcommand> [FLAGS] --manifest-path examples/tutor/Cargo.toml`
     (or `cargo anneal <subcommand>` from inside the crate directory).

### Invariant C — Relative vs. Absolute Path Flag Equivalence
- Every path-accepting flag (`--manifest-path`, `--workspace-root`,
  `--units-dir`, `--wrapper`, `--anneal-root`, both space-separated and `=`
  syntax) must work identically whether given:
  - a relative path with directory components (`examples/tutor/Cargo.toml`),
  - a bare relative filename (`Cargo.toml`) or `.` (`--anneal-root .`),
  - a path containing `.` or `..` segments (`./examples/tutor/../tutor/Cargo.toml`), or
  - an absolute path (`/abs/path/to/Cargo.toml`).
- Verify via `cargo test -p cargo-anneal --lib cli_parser_normalizes_relative_manifest_path_and_path_flags --locked`.

### Invariant D — Exact CLI Report Fidelity
- Every sample CLI report block (`Anneal Extract Summary:`,
  `Anneal Scaffold Summary:`, `Anneal Spec-Lock Summary:`,
  `Anneal Verification Summary:`) and error block in `docs/tutor/0*-*.md` is
  generated by a `<!-- tutor: report ... -->` or `<!-- tutor: errors ... -->`
  directive from a real run; `python3 docs/tutor/workflow/tutor_workflow.py lint`
  rejects any such block that lacks a directive. Fix drift by running
  `render`, never by editing the block.
- Report blocks elsewhere (`README.md`, `examples/tutor/README.md`) must match
  the exact line format emitted by `render_extract_report`,
  `render_scaffold_report`, `render_lock_specs_report`, and
  `render_verification_report` in `crates/cargo-anneal/src/lib.rs`.

### Invariant E — Durable Code & Theorem Synchronization
- Full-module listings of `Specs/FrameTutor/*.lean` and `Proof/FrameTutor/*.lean`
  in `docs/tutor/04-manual-proof-workflow.md` and
  `docs/tutor/05-verifying-unsafe-rust.md` are `<!-- tutor: file ... -->`
  transclusions of the files in the chapter crates (modulo `/-! ... -/` module
  header comments), and every committed chapter crate (`examples/tutor-ch1/`
  through `examples/tutor-ch4/` and `examples/tutor/`) must equal the previous
  one plus the edits its crate step in `tutor.toml` declares. Edit the crates
  and the step together, then `render`.
- Any Lean theorem names or signatures cited in prose (e.g., `Partial`,
  `MirContractHoldsWithSafety`, `safe_contractSpec_preserves_wellFormed`,
  `misplaced_contractSpec_violates_wellFormed`, `refineSafeSpec`,
  `verifyByWPSafe`, `dischargeRustEqU32`, `dischargeStatefulEq`) must exist in
  `trusted/lean/` or `theory/Anneal/`. Blocks that quote library sources
  (`trusted/lean/`, `theory/Anneal/`) are not generated; compare them against
  the current sources by hand.

## 3. Clean-Tree Rule After Manual CLI Runs

Running `cargo anneal` directly against a tutor crate (`examples/tutor/` or
`examples/tutor-ch1/` through `examples/tutor-ch4/`) leaves `target/`,
`.anneal/`, and `Cargo.lock` inside it. `.gitignore` excludes them
(`/examples/tutor*/...`); delete them to start a run from scratch:

```bash
rm -rf examples/tutor*/target examples/tutor*/.anneal examples/tutor*/Cargo.lock
```
