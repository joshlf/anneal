# Workbench branch agent guide

This orphan branch (`refs/heads/workbench`) is a self-contained Lean 4
experimentation, reusable-combinator, and proof-engineering library for Anneal
and related verification work. It lets agents share proven combinators,
reflective decision procedures, `#eval` exploration harnesses, and host
diagnostic scripts immediately without coupling rapid prototyping to `main`'s
multi-gate TCB review pipeline.

## Authority and review policy

1. **Canonical tip & linear history:** The tip of `refs/heads/workbench` is the
   canonical library state. Keep branch history strictly linear (no merge
   commits and no grafting of `main` history).
2. **Zero-review agent discretion:** Agents may add, generalize, or refine
   modules and scripts on `workbench` at their own discretion with zero human
   or PR review, provided `python3 tools/workbench.py check` passes on a clean
   working tree.
3. **Non-TCB status:** Nothing on `workbench` is part of Anneal's Trusted
   Computing Base (`trusted/`). Promoting a `pass1_portable` module from
   `workbench` into `anneal/theory/` or `anneal/correspondence/` on `main`
   remains subject to `main`'s full review and audit gates.
4. **Public repository hygiene:** This branch lives in a public repository.
   Never commit credentials, internal hostnames, private workstation paths,
   non-public identifiers, build caches (`.lake/`, `.olean`), symlinks, or
   blocking task markers. Begin every `.lean`, `.py`, and `.md` file with the
   Fuchsia copyright and license header.

## Purity and portability badges

`CATALOG.json` (generated by `python3 tools/workbench.py catalog`) classifies
every artifact under one of three mechanically checked badges:

- **`pass1_portable` (`lean/Workbench/Pass1/*.lean`):**
  Begins with `prelude`, imports only from Anneal's 51 locked `Init.*`
  foundation modules (or sibling `Workbench.Pass1.*` modules), uses only the 26
  tactics admitted by `TrustedBoundary.allowedTheoryTacticKinds`, emits zero
  `._unsafe_rec` or `isPartial` auxiliaries, and depends only on standard Lean
  axioms (`propext`, `Classical.choice`, `Quot.sound`). Files in this tier can
  be copied directly into `anneal/theory/` or `anneal/correspondence/` without
  rewriting tactics or recursion.
- **`lab_meta` (`lean/Workbench/Lab/*.lean`):**
  May import `Init`, `Std`, or `Lean` for `#eval` counterexample search,
  specification vacuity/sensitivity probing, and `Lean.Expr` DAG or marginal
  kernel-replay profiling. Must still compile cleanly with zero `sorryAx` and
  zero non-standard axioms. Never import `Workbench.Lab.*` from
  `Workbench.Pass1.*`.
- **`host_script` (`scripts/*.py`):**
  Executable Python 3.10+ standard-library CLI tools supporting `--help` and
  `--json`.

## Execution and resource governance

- Whenever `anneal-lean-run` is installed on the host (`$ANNEAL_LEAN_RUN` or
  `~/.local/bin/anneal-lean-run`), wrap CLI `lake` and `lean` invocations in
  `anneal-lean-run` so builds respect host cgroup memory caps and build slots.
  `tools/workbench.py`, `scripts/audit_lean_hygiene.py`, and
  `scripts/olean_profiler.py` discover and apply `anneal-lean-run`
  automatically when present.
- Prefer warm Lean LSP tools (`lean_diagnostics`, `lean_goal`,
  `lean_multi_attempt`) during interactive proof editing.

## Updating `workbench`

1. Edit or add files under `lean/Workbench/Pass1/`, `lean/Workbench/Lab/`,
   `scripts/`, or `tests/` (`chmod +x` on new scripts).
2. Regenerate the catalog and run the full self-validation gate:
   ```bash
   python3 tools/workbench.py catalog
   python3 tools/workbench.py check
   ```
3. Stage explicit paths and create a single linear commit on `workbench`
   preserving the `Agent-authored-by:` trailer convention. Keep upstream remote
   pushes gated on explicit user authorization when operating under local
   action-authority rules.
